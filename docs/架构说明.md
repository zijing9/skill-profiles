# 架构说明

> 面向想读懂代码或参与开发的人。**只讲结构，不讲操作**——操作看 README。

## 一句话架构

一个本地 Flask 服务 + 一个 pywebview 窗口，前端是一套静态页面，后端管「技能实体 + 目录链接 + git 版本」。

```
┌──────────────────────────────────────────────┐
│  pywebview 窗口（WebView2）                   │
│  └ static/index.html + app.js（单页，无构建）  │
└───────────────┬──────────────────────────────┘
                │ HTTP / JSON（127.0.0.1:8765）
┌───────────────▼──────────────────────────────┐
│  app.py（Flask）                              │
│   ├─ 路由层：/api/*                          │
│   ├─ 业务层：adopt / link / delete / detect… │
│   └─ core/                                   │
│       ├─ store.py     hub 仓库 + git         │
│       ├─ scanner.py   扫描技能根、读 frontmatter│
│       ├─ platform.py  平台差异（链接操作）     │
│       ├─ linker.py    platform 的业务封装     │
│       └─ logger.py    滚动日志                │
└───────────────┬──────────────────────────────┘
                │
        ┌───────▼────────┐      ┌──────────────┐
        │ data/hub/      │      │ 各技能根      │
        │  技能实体 + git│      │ ~/.dsh/skills │
        └────────────────┘      │ <ws>/.dsh/... │
                                └──────────────┘
```

## 核心模型：实体 + 链接

**技能实体只存一份**，放在 `data/hub/skills/<name>/`。

要让某个 agent 在某个位置用到它，就在那个位置放一个**目录链接**（Windows junction）指回实体：

```
data/hub/skills/example-skill/          ← 真身（唯一）
~/.dsh/skills/example-skill             ← junction → 上面
<工作区>/.dsh/skills/example-skill       ← junction → 上面
```

好处：改一处，所有挂载点同时生效；删掉链接不影响实体。

## 为什么需要 platform.py

Windows 的链接有三种（symlink / junction / 可追踪复制），权限要求不同。所有平台相关代码收敛在 `core/platform.py`，只暴露四个函数：

```python
is_link(path)          # 是不是链接
link_target(path)      # 指向哪
create_link(target, path)   # 建
remove_link(path)      # 删（只删链接，不删内容）
```

`core/linker.py` 只是业务封装，`core/scanner.py` 复用同一实现。要支持 macOS/Linux 只需改这一个文件。

## 数据流：一次「链接」操作

```
用户在界面点「链接」→ POST /api/link {name, root}
   ↓
app.py 校验权限与参数
   ↓
core/platform.create_link(hub_path, target_path)
   ↓
Store.commit("link: name -> ws:xxx")     ← git 留一条
   ↓
返回最新 STATE（前端整体重渲染）
```

**每次写操作都提交一条 git**，这是唯一的兜底手段（改错了能回滚）。

## 前端结构

单个 `static/app.js`（约 2300 行），无框架、无构建：

| 区块 | 职责 |
|---|---|
| `I18N` / `t()` / `setLang()` | 中英双语（只翻界面，不翻用户数据） |
| `navItems` / `renderNav` | 左侧导航（含子分类、拖拽排序） |
| `render` / `renderTrash` | 主区卡片、回收站 |
| `api()` | 统一 fetch 封装 + 错误提示 |
| `openDrawer` / `openReader` | 右侧详情抽屉、只读阅读器 |
| `showOnboarding` | 18 步聚光灯导览 |
| 各 `open*Dialog` | 新建 / 编辑 / 删除 / 设置 / 主题 / 切换 agent |

所有插入 HTML 的地方必须过 `esc()`，否则技能名里的 `<` `"` 会破版。

## CLI 与界面同源

`cli/skill.py` 是**独立进程**，直接 import `core/`，不走 HTTP：

```
界面 → Flask 路由 → core/
CLI  →  直接调用   → core/
```

所以两边的行为天然一致；`cli/cli.spec.json` 是给 agent 看的接口契约。

## 检测范围（重要约束）

只认两类位置，**不递归**：
- 全局：`<用户目录>/.dsh/skills`
- 工作区：`<工作区>/.dsh/skills`

工作区 = 父目录下「子目录里存在 `<agent>/skills`」的那些。完整规则见 `检测规范.md`。

## 目录职责

```
app.py              Flask 路由 + 业务逻辑（约 1400 行）
core/               与界面无关的底层能力
cli/                命令行（独立进程）
static/             前端（无构建）
tests/              18 个 CLI 契约测试
data/               运行时数据（不进 git）
  hub/              技能实体 + 独立 git
  trash/            回收站（10 天）
  config.json       配置
examples/           示例技能
docs/               设计文档、架构图
```

## 为什么不用框架 / 不用构建

- 单人维护，`React + Vite` 的构建链会让「改一行看效果」变成 30 秒
- pywebview 加载本地文件，单页无路由需求
- 代价：`app.js` 是个大文件，靠区域注释分区（搜索 `----------------` 可跳转）

## 已知技术债

| 位置 | 问题 | 影响 |
|---|---|---|
| `app.js` 单文件 | 2300 行，无模块化 | 改起来靠搜索 |
| `render()` 里 mixed 逻辑 | 过滤 / 排序 / 渲染混在一起 | 加视图成本高 |
| i18n key 靠字符串 | 没有类型检查，拼错会显示 key | 已通过静态扫描兜底 |
| 单实例互斥量 | 是全局的，同机不能跑两个副本 | 调试与正式不能同时开 |
